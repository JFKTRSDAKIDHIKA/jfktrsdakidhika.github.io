## TL;DR

- PAPI：利用 LLM 解码阶段的动态并行性做 PIM 加速。
- LLM decoding 的并行度随 batch/sequence 变化 → 需要动态适应。
- PIM 处理 memory-bound 的 attention + projection layers。

## Problem

LLM decoding 是 memory-bound（batch=1 时带宽利用率极低），PIM 如何针对性加速？

## Method

1. 分析 decoding 各阶段的 parallelism level
2. 高并行阶段用 GPU/NPU，低并行阶段 offload 到 PIM
3. Dynamic scheduling 在 host 和 PIM 间切换

## Insights

- LLM serving 的 prefill/decode 分离是共识 → PIM 适合 decode phase。
- "Dynamic parallelism" 是关键洞察：不同 token position 的并行度不同。
